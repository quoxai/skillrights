The SkillRights Registry

A public, append-only proof log for agent skills.

What it is

A record of existence

What existed, when, and under which declared terms. Recorded as hashes in a public proof log.

What it is not

Not a download store

Skill content stays on the author's machine. Only hashes and registration evidence enter the log.

Why list

Make your skill citable

Give your skill's existence and declared terms a public reference that others can cite and discover.

Register a skill#

See how it works: from a skill folder to the register →

From the skill directory, with the CLI (0.2.3 or later):

npx skillrights register            # unlisted: only the hash and evidence leave your machine
npx skillrights register --public   # adds name and description to this directory

Both modes return a permanent SRID and save a portable receipt (Merkle inclusion proof plus signed tree head) that is verified locally before it is written, and re-checkable offline forever with npx skillrights receipt. In unlisted mode the registration is real and provable but appears here only in the aggregate count, until you choose otherwise. Unlisted is not confidential: what you submit (hash, claimed author, key, signature, licence and mode) enters the public append-only log either way, and unlisted controls only this directory listing.

What it proves#

A registration proves three things: that this exact artefact (by SHA-256 hash) existed by the time the log recorded it (the log’s own clock; an independently witnessed time bound exists only once that root’s external anchor confirms, see the per-root anchor state); that a particular key and signature were submitted with it, and whether that signature verified against the registered hash; and the order of registrations relative to each other. A verified signature relates signed bytes to a key. It does not relate that key to a person or organisation, which is separate evidence the registry does not hold. Version lineage (supersedes) is a claim, recorded verbatim, never certified. Nothing here proves legal ownership.

Verify it yourself#

The log is designed to be checked without trusting us. For a single registration, upgrade its receipt to embed the Bitcoin proof (skillrights receipt --upgrade), then confirm it against the blockchain with independent tools: the full walkthrough, with a live worked example, is on the verify page. For the whole log, mirror the entries, recompute the Merkle root, and verify the external anchors. The anchoring worker requests an independent RFC 3161 countersignature for each new tree head and submits it to public OpenTimestamps calendar servers, which batch it into the Bitcoin blockchain; a fresh root reads as pending for a few hours until that confirmation lands, and the per-root state is always live at /api/v1/log/anchors (and in the evidence line at the top of this page). The recipe, with exact commands, is in MIRRORING.md.
