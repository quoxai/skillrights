Verify a receipt without us

A SkillRights receipt is designed to outlive SkillRights. This page shows how to confirm one against the Bitcoin blockchain using independent tools, so that even if this registry and this company vanished tomorrow, the proof still holds.

What the receipt actually proves#

When you register a skill, we never see the skill. We record the SHA-256 hash of its signed manifest as one leaf in a public, append-only Merkle tree. Periodically the current tree root is submitted to public OpenTimestamps calendars, which batch it into a Bitcoin transaction. Once that transaction is mined, the root is permanently committed to a Bitcoin block.

That gives you a chain with four links, and only the last of them touches the Bitcoin network:

  1. Your file to a leaf The SHA-256 of your signed manifest is the leaf. You recompute it from the manifest in your own directory.
  2. The leaf to a Merkle root An RFC 6962 inclusion proof, carried inside the receipt, shows your leaf sits in a tree with a specific root. This is arithmetic: hashing pairs of hashes until you reach the root. No signature, no server.
  3. The root to a Bitcoin block The OpenTimestamps proof, also carried inside the receipt, commits that exact root into a named Bitcoin block. This is what the independent ots tool checks.
  4. The block is real You confirm that Bitcoin block on any block explorer, or your own node. Bitcoin, not us, is the witness.

Our signing key appears nowhere in that chain. It is a convenience for checking a fresh receipt in the first few hours before Bitcoin confirmation lands, not the basis of the proof. That is the whole point: the durable evidence is in Bitcoin, and Bitcoin does not need us.

Step 1: make the receipt self-contained#

A fresh receipt carries the inclusion proof and a signed tree head. Once its root has been anchored to Bitcoin (usually within a day), upgrade the receipt to embed the Bitcoin proof itself. After this, the receipt file is the whole story and needs nothing from us.

embed the Bitcoin proof
skillrights receipt --upgrade ./my-skill

Anchored: this receipt now verifies against Bitcoin block 966403.
Merkle root 7d81…5624 is committed into that block by the embedded
OpenTimestamps proof. Saved. It no longer needs the registry to prove it.

Step 2: verify offline, with no registry#

This recomputes the whole chain from your file to the Bitcoin-committed root using only the receipt and the tool on your machine. Turn off your network first if you want to prove it to yourself.

offline check
skillrights receipt --offline ./my-skill

Bitcoin:    anchored in block 966403 (verified offline, no registry needed).
            Merkle root 7d81…5624 is committed to Bitcoin by the embedded
            OpenTimestamps proof.

This step confirms every link except the last: it does not, by itself, prove the Bitcoin block is genuine. For that you go to Bitcoin directly.

Step 3: confirm the block against Bitcoin itself#

Extract the OpenTimestamps proof as a standalone file and check it with tools that have nothing to do with SkillRights.

extract the proof
skillrights receipt --extract-ots ./my-skill
# writes sr_skill_<id>.ots and prints the exact commands below

Install the independent OpenTimestamps client (pip install opentimestamps-client). If you run a Bitcoin node, one command closes the loop:

with a Bitcoin node
ots verify -d <merkle-root> sr_skill_<id>.ots

If you do not run a node, read the proof and check the block on a public explorer. ots info prints the Bitcoin block the proof commits to and the block merkle root it expects:

read the proof, then check the block
ots info sr_skill_<id>.ots
    ...
    verify BitcoinBlockHeaderAttestation(966403)
    # Bitcoin block merkle root 97dc58699ea1d8ec03ef9620eb0a49f580fe4227ea52d10b822d8baf36381531

Then open that block on any explorer and confirm it shows the same merkle root. Use whichever you trust:

  • mempool.space/block/966403
  • blockstream.info (block height 966403)
  • your own bitcoin-cli getblock <hash>

If the block's merkle root matches the one the proof expects, and your file recomputed to the leaf the proof starts from, then your skill's hash is provably older than that Bitcoin block. Nobody, including us, can move that date.

A worked example you can run right now#

The very first entry in our public log is a live, checkable case. You do not need our page for any of this:

sr:skill:01M26A1FG6KZ0A994WBQJEWY7Q

97dc58699ea1d8ec03ef9620eb0a49f580fe4227ea52d10b822d8baf36381531

Fetch the raw log entry from the public API, recompute its leaf, and you get the root above. Fetch the OpenTimestamps proof for that root, run ots info, and it names block 966403 and the merkle root above. Open block 966403 on mempool.space, and its merkle root is that same value. Three independent sources, one answer.

Why this design

A registry that is the only witness to its own records is worth exactly as much as your trust in the company running it. Bitcoin anchoring removes that dependency. The receipt in your hands, plus a public blockchain, is enough. We are convenient, not load-bearing.

Going further: mirror the whole log#

To check not just one receipt but the integrity of the entire log, mirror every entry, recompute the Merkle root, and verify the external anchors yourself. The full recipe, with exact commands, is in MIRRORING.md. Live anchor state for every root is at /api/v1/log/anchors.
